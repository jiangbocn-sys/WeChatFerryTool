### 1. 密钥采集与离线解密（全链路打通）

| 内容 | 结果 |
|---|---|
| 定位可靠钩点 | **`sqlcipher_api_routines->key`**（`Weixin.dll + 0x8BB1570`，成员 +0x10）——每次开加密库必调。原先挂的 `codec_get_key`（`0x4EE64D0`）**实测根本不触发**，aixed 源码自己都注释"可以废弃不用" |
| 新项目 | `D:\projects\WeChatKeyHook`（keyhook.cpp / build.ps1 / inject_early.ps1 / README） |
| 当前生效 DLL | `keyhook3.dll`（三钩点：`routines->key` 首选 + `key_v2` + `codec_get_key` 兜底） |
| 采集结果 | 17~19 把密钥 |
| 解密 | `message_0.db` / `message_fts.db` / `message_resource.db` 全部解开 |
| 关键发现 | 密钥以 SQLCipher **`x'<hex>'` 文本形式**传入 → 必须**当口令原样透传**；写成 `'x{hex}'`（缺收尾引号）会走 KDF，必然失败（已实测证伪） |
| 密钥稳定性 | **重启微信后旧密钥仍能开库** → 不需要每次启动都采（推翻了 STATUS.md 里"每次启动重新生成"的旧推断） |

### 2. 微信 4.x 库结构（实测，已写进 `docs/db_backfill.md`）

* `message_0.db` 是**每会话一张表**：`Msg_<md5(会话id)>`（实测 62 张）+ `Name2Id`
* `Name2Id.rowid` 就是消息表 `real_sender_id` 指向的 id；`ruibo_jiang` = rowid 2（自己）
* 列名：`server_id`(MsgSvrID) / `create_time` / `local_type` / `real_sender_id` /
  `message_content` / `WCDB_CT_message_content`
* **列压缩**：`WCDB_CT_* == 4` → zstd 帧；`== 0` → 明文 str（注意是 `str` 不是 `bytes`）
* **`-wal` 有 4MB，最近记录都在里面，必须一起复制**
* 方向判定：`real_sender_id == 自己的 rowid` → out

### 3. 离线回填

`scripts/db_backfill.py`：key×db 配对（试错矩阵 + 缓存）→ 提取私聊 → 按 `msg_id` 去重入库。
实测：**641 条私聊，其中 433 条是 hook 漏掉的**（漏抓率约 68%，与你说的"时有时无"吻合）。

### 4. 账号隔离

`paths.py`：每个微信账号一套数据根 `accounts/<账号目录名>/`。
**`self_wxid` 由账号目录名推导**（`ruibo_jiang_542e` → `ruibo_jiang`）——
这修掉了"换账号后自己发的消息被当成别人发的、自动回复回你自己"的风险。
首次运行会把旧 `data/logs/reports` **复制**（不移动）进账号目录。

   加账号隔离时只动了后者，前者跟着变，导致找不到 `config.yaml`。
