# 群知识库问答（设计 + 实现记录）

> 用户需求（2026-10-15 确认）：
> 资料目录按群配置（`D:\JiangBo\Documents\wechatdocs\{可师风水,弟子群}`）；
> 只做**文字**蒸馏（图片忽略）；消息**以 `@虚拟号` 开头**即触发，名字**按群可配**；
> **任何人的问题都答**；**助教第三人称**口径；回答**严格限定资料内容**；
> 每群**限速 2 分钟一条** + 连续提问**排队**（队列上限 10、同人去重）；
> 默认 `test_only` 先观察。

## 一、为什么这样设计（关键取舍）

| 决策 | 理由 |
|---|---|
| **两段式：蒸馏笔记 + 检索片段**，不是每次喂全部资料 | 资料 252,155 字（≈32 万 token），每问一次全喂既贵又慢 |
| 笔记**按原文件分**（不是按主题合并） | 可追溯；某文件更新只重写它自己那份；可人工修 |
| 检索用 **BM25 + 中文 bigram**，不用向量库 | 0 新依赖、0 额外费用、**可解释**（能说清命中了哪段、为什么）、出错可人工修 |
| 回答后**第二遍独立自检** | 只靠提示词写"不要编造"不可靠（本项目在总结功能上反复验证过） |
| `.doc`/`.ppt` 走 **Office COM（PowerShell 子进程）** | 本机有 Office；不必给冻结 exe 加 `pywin32` |
| 只 `pip install pypdf` | 其余 8 种格式全靠标准库 |

| 文件 | 职责 |
|---|---|

产物布局（`<数据根>/kb/<群>/`）：

```

text/<原文件名>.txt 抽取出的文字稿（复查 + 增量缓存）
```

## 三、增量：资料增加后如何再次蒸馏（三种激活）

| 方式 | 触发点 | 说明 |
|---|---|---|
| **手动**（默认靠这个） | `tools/kb.py distill --yes`，后续接页面按钮 | 你放完资料点一下，**只蒸变化的** |
| 定时 | 配置 `kb.auto_distill_time`（默认空=关） | 每天到点比对指纹，**没变化就不调 LLM** |
| 启动 | app 启动时比指纹（只抽文字） | 重启后新文字立即可用 |

判定规则（`fingerprint_changed`）**顺序很重要**：

1. 抽取器版本变了 → 重抽（我改归一化规则后老文字稿不会陈旧）；
2. **size 或 mtime 变了 → 直接重抽**；
3. 两者都没变才比 sha256。

⚠️ 第 2 步不能省：曾经写成"有 sha256 就只比 sha256"，那样在 **mtime 不更新**的场景
（网盘按内容同步、只读挂载、容器里拷文件）会**静默漏掉内容更新**。

## 四、踩过的坑（都在回归里锁住了）

1. **PDF/`.doc` 逐字换行**：`'六\n爻·\n讲\n义'` → 需归一化，否则白烧 token 且语义破碎。
2. **归一化改错两次**：结构行（列表项/标题）**直接写进输出、从不留在缓冲区**，
   导致"下一行的续行合并"逻辑**根本没执行** —— 前两次都在改判定条件，其实那段代码没跑到。
   修法：结构行也留在 `buf` 里，由下一行决定是否续接。
3. **台账只在整轮结束才写** → 进程被中断后已蒸馏的文件**不记账**，下次重蒸（白花额度）。
   修法：**每个文件处理完立即落盘**。
4. **检索不到就该沉默**：无关问题 → `资料中未涉及这个问题，建议请教老师`，
   且**不调 LLM**（0 次调用）。
5. **`@小易` 只 @ 不说话** → 必须当"没触发"，否则空问题白花一次调用。

## 七、已知限制

* `.doc`/`.ppt` 依赖本机 Office（COM）；Office 缺失时该格式报错、其它格式照跑；
* PDF 若是**扫描件**（无文字层）→ 明确报"取不到文字"，**不产出空笔记**；
* pptx 的**图表/SmartArt** 文字取不全（已明确标注，不假装成功）；
* 归一化仍有约 1%~2% 的排版硬断无法与真实句末区分（如"…。男人 / 掌家…"），
  不影响语义，不再过度优化；
* 回答**不保证 100% 无越界**（自检是尽力而为的独立校验），故回复固定带免责尾。
